# Social Graph Metrics — One Pager

## Why These Metrics

Daily aggregation of connections, invites, civility, and heatmap bins gives product, operations, and trust teams a fast pulse on community health. The ETL job `social:metrics-daily` captures these points for every persona and surfaces them to the Connections Hub experience and admin dashboards.

## Metric Snapshot

| Metric | Definition | Calculation Source | Primary Surfaces |
| --- | --- | --- | --- |
| **Total Connections** | Accepted relationships a persona has accumulated up to the capture day. | Counts `connections` rows with status `accepted` involving the persona’s `user_id`. | Connections Hub hero card, Admin › Social Metrics Dashboard (cards + persona table). |
| **Invites Sent** | Number of invites initiated by the persona during the capture day window. | Counts `invites` where `sender_profile_id` matches persona and `created_at` is within the day. | Connections Hub “Invite outbound” tile, Admin › Social Metrics Dashboard. |
| **Invites Accepted** | Invites from the persona that were accepted during the capture day window. | Counts `invites` with `accepted_at` inside the day. | Connections Hub funnel widget, Admin › Social Metrics Dashboard (Invites column). |
| **Messaging Civility Score** | Trust/safety signal indicating how respectful outbound conversations were for the day. | `100 - ((incident_reports / max(messages_sent,1)) * 100)` using messages & incident reports for the persona. | Connections Hub trust ribbon, Ops › Trust & Safety drill-downs, Admin › Social Metrics Dashboard (Civility column). |
| **Connection Heatmap Bins** | Rolling 7-day snapshot of daily accepted connection counts plus pending inbound/outbound requests. | Aggregated daily connection counts + pending queries, persisted as `connection_heatmap_bins` JSON. | Connections Hub activity heatmap, Admin › Social Metrics Dashboard (table columns for pending incoming/outgoing), future Ops dashboards. |
| **30-Day Heatmap Bins** | Extended rolling snapshot for the last 30 days so planners can spot longer-trend surges or drop-offs. | Persisted separately as `connection_heatmap_bins_30d` JSON generated by the ETL when extended heatmaps are enabled. | Admin dashboards and Ops notebooks that chart cohort growth, plus future Connections Hub toggle for 30D range. |
| **Primary Cohort Tag** | Canonical cohort label (first value from `cohort_tags`) to support indexed filtering and segmentation. | Derived in `SocialMetricsAggregationService::deriveCohortTags()` and stored as `primary_cohort` (nullable, indexed with `captured_on`). | Admin persona table cohort filters, analytics warehouse exports, and future UI chips for segmentation. |

## Where The Data Flows

1. **ETL Pipeline**
   - Command `php artisan social:metrics-daily [--persona=ID] [--force]` runs the `SocialMetricsEtlPipeline` which wraps `SocialMetricsAggregationService`.
   - Facts land in `social_metrics_daily` with JSON bins for heatmaps/invite funnels.
   - Logs emit to the dedicated `etl` channel (`storage/logs/etl.log`).
2. **Connections Hub (frontend/social/connections)**
   - Persona-level cards read from `SocialMetricsDaily` for the selected day to render connection totals, invite funnel, civility badge, and the heatmap widget.
3. **Operations Dashboards**
   - `resources/views/admin/analytics/social-metrics.blade.php` shows aggregated cards, 7-day trend chart, and persona snapshot for admin and trust teams.
   - `admin/etl/monitor` provides a lightweight pipeline monitor summarizing last capture date, personas processed, and recent fact loads.

## How To Extend

- Add new KPIs by expanding `SocialMetricsAggregationService::buildMetricsForProfile()` and updating the `connection_heatmap_bins`/`invite_funnel_bins` payloads.
- Surface additional cards in Connections Hub by reading from the same fact table—no schema change needed for basic counters.
- Register new ETL pipelines by subclassing `App\Support\Etl\EtlPipeline` and adding them to the ETL dashboard’s `$pipelines` array.

Keep this page updated as new metrics or destinations come online so product, ops, and trust stakeholders share one canonical reference.
